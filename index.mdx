QuotaMint is the runtime layer for products that need to answer one question reliably: **can this customer use this feature right now?**

It keeps customer plans, feature access, usage, and credits in one place. Your application remains responsible for billing and business logic; QuotaMint enforces the usage decision in your request path.

## What QuotaMint owns

- Plan assignment and feature entitlements
- Atomic credit deduction and append-only credit history
- Usage events and usage reporting
- Idempotency for retries and concurrent requests
- Test and live API keys
- Webhook notifications for usage and credit state

## What QuotaMint does not own

QuotaMint is **not** a payment gateway, checkout system, tax service, or API gateway. Keep Stripe, Razorpay, Paddle, Lemon Squeezy, or your own billing system for payments. When a subscription changes, your backend syncs the resulting plan into QuotaMint.

## Two surfaces, one data model

The dashboard is the human-facing control plane. The runtime API is the machine-facing data plane.

```text
Your dashboard or billing webhook
        │  internal service API
        ▼
  Control plane ─────────── PostgreSQL ─────────── Runtime API
  workspaces, plans, keys                          check, consume, events
  customers, settings                              atomic credits + usage
        ▲                                          ▲
        └──────────── dashboard reads ─────────────┘
```
