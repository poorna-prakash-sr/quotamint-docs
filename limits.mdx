# Limits and plans

Account plans apply to a workspace.
All plans include checks, consumption, credits, idempotency, Test and Live environments, and API authentication.

Usage counters reset on the first day of each UTC calendar month.
Plan changes do not erase data or reset counters.

## Request limits

For the public runtime API:

- `customerId`: up to 255 characters
- `feature` and `event`: up to 120 characters
- `quantity`: integer from 1 through 1,000,000
- `idempotencyKey`: up to 255 characters
- Request metadata: a JSON object within your plan's byte and key limits
- Request body: up to 64 KiB by default
- Event timestamps: no more than five minutes in the future

Identifiers cannot contain whitespace or control characters.

## What happens at a limit

- A request-rate limit returns HTTP `429` with `rate_limited` and a `Retry-After` header.
- A monthly event limit returns HTTP `429` with `workspace_usage_limit_exceeded`.
- A project, API-key, member, or webhook capacity limit blocks new creation while existing resources remain available.
- Downgrading does not delete existing projects, keys, members, endpoints, usage, or audit records.
- Retained data outside the selected history window is not queryable or exportable from the dashboard.

See [Errors](/api/errors) for response handling.
