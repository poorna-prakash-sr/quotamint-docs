# Quickstart

This guide takes you from a new QuotaMint account to a server-side `consume` request.

## Prerequisites

You need:

- A QuotaMint account
- Access to create a workspace, project, plans, features, and API keys
- A Node.js backend, or any backend that can send HTTPS requests

<Warning>
  Never put a QuotaMint API key in browser, mobile, or other untrusted client code.
  Store it in your backend environment and keep Test and Live keys separate.
</Warning>

## Create your project

<Steps>
  <Step title="Create a workspace">
    Sign up, then create a workspace for your company or team.
    A workspace contains your projects, members, account plan, and workspace-level limits.
  </Step>
  <Step title="Create a project">
    Create a project for the product or service that will use QuotaMint.
    New projects start in the Test environment.
  </Step>
  <Step title="Create a plan">
    Add a plan and set its monthly credit allowance.
    Monthly credits are granted once per active customer each calendar month.
  </Step>
  <Step title="Create a feature">
    Add the product action that your backend will meter, such as `image_generation`.
    Select a feature type and, for credit features, set the cost per unit.
  </Step>
</Steps>

## Install the Node.js SDK

```bash
npm install @quotamint/node
```

The SDK is for server-side Node.js applications. You can also use the REST API from any backend language.

## Create a Test API key

In the dashboard, open **API keys**, choose **Test**, and create a key.
Copy the secret when it appears. QuotaMint shows the secret only once.

Set it in your backend environment:

```bash
QUOTAMINT_API_KEY=qm_test_replace_with_your_key
```

Also set the runtime URL shown on the **Developers** page:

```bash
QUOTAMINT_BASE_URL=https://your-runtime.example.com
```

## Initialize the client

```ts
import { QuotaMint } from "@quotamint/node";

const quotamint = new QuotaMint({
  apiKey: process.env.QUOTAMINT_API_KEY!,
  baseUrl: process.env.QUOTAMINT_BASE_URL!,
});
```

## Charge a feature

Call `consume` from the backend when your application is ready to perform the action.
Use a stable idempotency key for the logical operation, not a new random key for every retry.

```ts
const decision = await quotamint.consume({
  customerId: "customer_123",
  feature: "image_generation",
  quantity: 1,
  idempotencyKey: "image-job-8472",
});

if (decision.allowed) {
  // Start the image job.
  console.log(`Charged ${decision.creditsUsed} credits`);
} else if (decision.reason === "insufficient_credits") {
  // Show an upgrade or top-up message.
} else {
  // The customer's plan does not allow this action.
}
```

A successful response includes the remaining balance.
A denied decision uses the same successful HTTP status and returns `allowed: false` with a reason.

## Test before going Live

Use the Test environment while you build your integration.
Test customers, balances, usage, and API keys are separate from Live data.

When you are ready:

1. Create a Live API key.
2. Add it to the production backend environment.
3. Use the Live runtime URL and Live customer records.
4. Keep the Test key available for development and staging.

<Check>
  You are ready when a backend request can consume a Test feature and the result appears in the dashboard usage history.
</Check>
